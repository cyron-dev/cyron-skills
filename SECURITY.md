# Security

## Reporting a problem

Do not open a public issue containing credentials, customer information, private project data, or a working exploit. Contact the repository owner privately first.

## Publishing checklist

Before publishing a release:

- Search for passwords, tokens, private keys, internal URLs, IP addresses, customer names, and local absolute paths.
- Review fixtures and examples for production data.
- Confirm project-specific rules are intended for public distribution.
- Verify scripts do not perform destructive actions outside their documented scope.
